# dns-net v0.3.0 - DNS over TLS

**Lookups nobody on the path can read or change.** With the `tls` feature, upstreams are reached over TLS only (RFC 7858), checked by certificate or by a pinned key, with queries padded so their length tells nothing. Every lookup also reports whether the upstream validated it with DNSSEC, when that report can be trusted.

```rust
use dns_net::{Resolver, ResolverConfig, Upstream};

let resolver = Resolver::new(
    ResolverConfig::new().upstream(Upstream::tls("9.9.9.9:853".parse()?, "dns.quad9.net")?),
)?;
let mx = resolver.lookup(&"example.com".parse()?, dns_net::RecordType::MX)?;
let validated = mx.authenticated();
```

## What is dns-net?

A DNS client for Rust: a strict, sans-IO message codec, and a caching stub resolver on net-io's reactor driver that never blocks a server worker, with defences against forged answers and an address policy against server-side request forgery.

## What's in 0.3.0

- **DNS over TLS** (feature `tls`, through tls-net). `Upstream::tls` checks the certificate's chain and name; `Upstream::tls_pinned` checks the SHA-256 of the server's public key, for a server with its own certificate.
- **One connection per upstream.** Queries share it, each with its own id, and replies may come in any order. It closes after 10 seconds with nothing in flight; a server that closes it first costs a new handshake on the next query.
- **Padding.** Queries are padded to multiples of 128 bytes (RFC 8467).
- **No plaintext fallback.** A configuration is all TLS or all plain, a failed handshake is `Error::Tls`, and a truncated reply over TLS is refused, never retried in the clear.
- **`Lookup::authenticated`.** True when every reply behind the answer had the AD bit set and came over TLS or from a resolver on the same machine. An AD bit from a plain upstream across a network is never reported.

## Costs

Measured on Linux on loopback at a load average of about 20, so upper bounds:
- A lookup on a reused TLS connection costs the same as over UDP: 185 against 191 microseconds median.
- A new connection's handshake adds about 0.75 ms on loopback, and three network round trips on a real path.
- Padding adds at most 127 bytes to a query.

## Changed

- `Upstream` is no longer `Copy`.
- `Answer` is `#[non_exhaustive]` and carries `authentic`.
- Every query sets the AD bit.

## Known gaps

- No DNS over HTTPS yet (0.4.0).
- Windows upstreams are still read from the registry through `reg.exe`.

## What's next

`0.4.0`: DNS over HTTPS on http-net, and the answer-agreement experiment.

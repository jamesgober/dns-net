# dns-net v0.2.0 - Resolver

**A DNS client that never blocks a server worker, and refuses forged answers and private addresses.** v0.2.0 is the first working release: a strict, sans-IO message codec, and a caching stub resolver on net-io's reactor driver.

```rust
use dns_net::{PublicOnly, Resolver, ResolverConfig};

let resolver = Resolver::new(ResolverConfig::system()?)?;
// A URL a user gave you: loopback, private, and metadata addresses refused.
let addrs = resolver.lookup_ip_with("hooks.example.net", &PublicOnly::new())?;
```

## What is dns-net?

A DNS client for Rust. The codec reads and writes messages without I/O and refuses anything two readers could take differently. The resolver multiplexes every query on one thread, caches answers within a byte budget, and hands results to blocking callers, callbacks, or net-io sessions parked on a worker.

## What's in 0.2.0

- **The codec.** Names with decompression that only moves backwards (at most 127 pointers and 255 bytes per name), the header, the question, all three sections, and EDNS(0). Typed data for A, AAAA, NS, CNAME, PTR, SOA, MX, TXT, SRV, and CAA; other types kept as bytes.
- **Answers that cannot be forged cheaply.** Each query goes out on a fresh socket on a random port, connected to the upstream, with a random id and the name in random case. A reply must repeat all of it, and only the records on the chain from the question to its answer are used or cached. Identical questions in flight share one query.
- **The resolver.** Upstreams from `/etc/resolv.conf` or the Windows adapter settings, UDP with TCP on truncation, retries and failover, a cache of positive and negative answers with TTL caps, and limits on queries in flight and lookups waiting.
- **Lookups from the reactor.** `Resolver::park` and `park_ip` return a ticket and wake the parked net-io session when the answer arrives; a cached answer is ready at once.
- **An address policy at resolve time.** `PublicOnly` refuses loopback, private, link-local, metadata, and the other special-purpose addresses on every lookup, cached or not, which stops server-side request forgery and DNS rebinding as long as the caller connects to the addresses returned. Host names that URL parsers read as IPv4 (`127.1`) are refused.
- **Local names stay local.** `localhost` answers loopback; `.invalid` and `.onion` names do not exist.

## Costs

Measured on Linux at a load average of about 10, so upper bounds: 68 ns to build a query, 158 ns to check a reply, 86 ns to read its answer, 1 ns to refuse a reply with another id, 189 ns for a lookup answered from the cache.

## Known gaps

- **Windows** waits for a net-io release that registers UDP sockets with its IOCP driver.
- No DNS over TLS or HTTPS yet, and no DNSSEC reporting (0.3.0 and 0.4.0).

## What's next

`0.3.0`: DNS over TLS through tls-net, and the AD bit from a validating upstream.
